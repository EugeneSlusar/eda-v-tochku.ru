# Передача контекста: лендинг «Еда в точку»

Документ описывает всё, что сделано и решено в рабочем диалоге, чтобы продолжить в новом диалоге. Актуален на 2026-11-04.

## 1. Проект
- Лендинг умного холодильника со свежей едой для офисов в Тольятти: `index.html`, `landing.css`, `submit.php`, `images/`. Сборки нет.
- Домен `eda-v-tochku.ru`. Показываются только публичные факты (см. раздел 5).
- Владелец репозитория: `EugeneSlusar`. Репозиторий `EugeneSlusar/eda-v-tochku.ru`. Рядом есть репозиторий `sync-repo.orgbox.net` (скрипт деплоя `.deploy/sync_repo_from_git.sh`), в этом проекте он не меняется.

## 2. Ветки и работа с Git
- `main` — боевая, пуш запускает деплой. Ветка по умолчанию на GitHub, судя по клону, `landing/standalone` (там старая версия): желательно переключить default на `main` в настройках репозитория (Settings → Branches) или говорить новой сессии «работай от `main`».
- Новые правки идут в `landing/<задача>`. Владелец сливает сам или просит Claude («слей»).
- Ветки, полностью вошедшие в `main` (можно удалить): `landing/commercial-offer-content`, `landing/publish-to-public-html`, `landing/infographic-images`, `landing/lead-form`, `landing/chat-id-diagnostics`, `landing/illustrations-v2-issue-1`, `landing/issue-1-v3-layout`, `landing/handoff-docs`, `landing/standalone`.
- Три ветки намеренно НЕ слиты и сохранены как архив (ничего не потеряно), в `main` их сливать не нужно:
  - `landing/layout-v3` — моя прежняя раскладка блоков с картинками, заменена раскладкой из PR №4 (конфликты в `index.html` и `landing.css`).
  - `landing/graphics-issue-1` — закрытый PR №2: 7 SVG-сцен холодильника, включая `use-*` для блока «Кому это нужно». Слияние вернуло бы SVG в `images/`, что запрещено проверкой `image-audit`, и сломало бы раскладку.
  - `landing/domain-eda-ru` — одна правка `README`, в которой неверно описан `DEPLOY_PATH` (на деле `DEPLOY_PATH` — родитель `public_html`).
- Слитые PR: №3 (иллюстрации v2, отклонены по качеству), №4 (раскладка v3, частично). №2 закрыт без слияния.

## 3. Деплой на сервер
- Workflow `.github/workflows/deploy.yml`: на пуш в `main` или вручную по SSH заходит в `DEPLOY_PATH` и запускает `bash .deploy/sync_repo_from_git.sh --auto`, затем копирует `index.html`, `landing.css`, `favicon.png`, `robots.txt`, `submit.php` и папку `images/` в `PUBLISH_DIR` (по умолчанию `public_html`).
- Секреты GitHub: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`, необязательно `DEPLOY_PORT`, `PUBLISH_DIR`.
- Структура на сервере: репозиторий в `~/eda-v-tochku.ru` (это `DEPLOY_PATH`), веб-корень `~/eda-v-tochku.ru/public_html`. Рядом лежат `.env` и `.leads/` (вне веб-корня).
- Новые файлы сайта нужно добавлять в строку `cp` в `deploy.yml`, иначе они не попадут в `public_html`. Так уже терялась папка `images/`.
- История: первый деплой падал из-за лишнего файла `.github/workflows/deploy.yml` в `DEPLOY_PATH` (удалили на сервере). С run #2 деплои успешны (последний проверенный — run #9).
- Деплой проверялся только по логам Actions. Сам сайт из облачной сессии не открывается: домен недоступен или режется прокси.

## 4. Форма заявки и MAX
- Форма отправляет `POST submit.php` (нужны PHP и расширение curl). Заявка пишется в `~/eda-v-tochku.ru/.leads/leads.csv` (UTF-8, разделитель `;`) и уходит сообщением в канал или группу MAX. Если MAX недоступен, заявка остаётся в файле, ошибка пишется в `.leads/errors.log`.
- Защита: поле-ловушка `website`, не больше 5 заявок за 10 минут с IP, экранирование формул в CSV, валидация, чекбокс согласия.
- Настройки только в `~/eda-v-tochku.ru/.env` (в Git не попадает, образец `.env.example`): `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, необязательно `MAX_API_BASE` (по умолчанию `https://platform-api2.max.ru`), `MAX_CA_BUNDLE` (если хостинг не доверяет сертификату Минцифры), `LEADS_DIR`.
- Запрос в MAX: `POST {base}/messages?chat_id=ID`, токен в заголовке `Authorization`, тело `{"text": "..."}` без разметки.
- `chat_id`: отправить по названию группы нельзя. Список групп бота API MAX не отдаёт. ID приходит только в событиях (`bot_added`, `message_created`). Бот должен быть администратором группы, иначе события из группы не приходят. Если у бота включён вебхук (`POST /subscriptions`), long polling не работает. Помощник: `php tools/max-chat-id.php [ТОКЕН]` (токен из `.env`, проверяет токен и вебхуки, ждёт событий).
- Статус: владелец дал боту права администратора, получил `chat_id` и заполнил `.env`. Реальная тестовая отправка ещё не подтверждена. Проверка: отправить заявку с сайта, при ошибке смотреть `.leads/errors.log` (401 — токен, 400/404 — `MAX_CHAT_ID`, ошибка сертификата — `MAX_CA_BUNDLE`).
- Проверялось на локальном PHP 8.3 с подставным сервером MAX; с настоящим MAX не проверялось.

## 5. Контент и решения
Факты из коммерческого предложения (на сайте уже есть):
- Холодильник ставится бесплатно, полностью за счёт поставщика; обслуживание и пополнение на стороне поставщика.
- Место около 1 м² и розетка 220 В; оплата сотрудниками в приложении по QR-коду.
- Компенсация электроэнергии принимающей стороной 500–750 ₽ (период в КП не указан, на сайте без периода). Возможна выплата аренды за место.
- Экономия времени сотрудников 30–60 минут в день, рост продуктивности и лояльности, имидж работодателя.
- Лучше всего подходит: офисы от 30 человек, бизнес-центры, производства, логистика, медицинские и образовательные учреждения.

Решения:
- Личные контакты (телефоны, Telegram) на сайт не выкладываем: CI блокирует телефон и email в `index.html`.
- Пометки «Уточнить» остаются: интернет и доступ курьера, порог, при котором холодильник забирают, реквизиты и политика конфиденциальности, ссылка на политику у чекбокса согласия.
- Домен остаётся `eda-v-tochku.ru`; вариант `еда.ру` отклонён.

## 8. Подводные камни
- Стоп-хук в облачной сессии пишет «N непушенных коммитов, нет удалённой ветки». Причина: клон мелкий и single-branch, нет `refs/remotes/origin/<ветка>`. Проверить `git ls-remote origin refs/heads/<ветка>`; если коммит там, создать ссылку `git update-ref refs/remotes/origin/<ветка> HEAD` и вернуться на `main` (`git checkout -B main origin/main`). Для `main` помогает `git config --add remote.origin.fetch '+refs/heads/main:refs/remotes/origin/main'`.
- Пуш через прокси иногда занимает больше двух минут; выполнять с `timeout 110` и затем сверять `git ls-remote`.
- Локальный `origin/main` в мелком клоне устаревает: перед сливом всегда `git fetch origin main:refs/remotes/origin/main` и проверять `git merge-base --is-ancestor origin/main HEAD`.
- Скриншоты: Playwright предустановлен; нужно прокрутить страницу, чтобы сработал `loading="lazy"`, иначе в `fullPage` картинки пустые.
- Внешний доступ: `https://re-fresh.net` из облака недоступен (reset), по HTTP отдаёт заглушку парковки. Контент оттуда брать из присланного текста КП.
